# Dependencies for the unattended daily refresh (.github/workflows/daily-refresh.yml).
#
# Separate from requirements.txt, and FULLY PINNED, for one reason: this is the file a
# job installs from every morning while nobody is watching. An unpinned transitive
# release is a cron that breaks on a day the data quietly stops refreshing — the exact
# failure the freshness conditions exist to detect and this file exists to prevent.
# requirements.txt stays unpinned; the constraint is about the automated path.
#
# The whole resolved closure is pinned, not only the six direct dependencies. Pinning
# direct deps alone leaves every transitive package free to move, which is where this
# class of breakage actually comes from.
#
# Contents are derived from a static import walk of the daily path — ingest, matchrec
# schema/trades/rank, model.scale --backfill, export_model_service, export_demo_board,
# export_firm_boards — and tests/test_daily_dependencies.py re-runs that walk and fails
# if an import appears here that this file does not cover. Two of the six were invisible
# to inspection because they are imported inside functions rather than at module top
# level: lightgbm (model/scale.py load_estimators) and sentence-transformers
# (model/embeddings.py). That is why the daily refresh died mid-run rather than at
# import time.
#
# Deliberately ABSENT, because the daily path never uses them: streamlit (the superseded
# ui/app.py), openai and pdfplumber (the extraction path, which makes API calls the cron
# must never make).
#
# torch comes from PyTorch's CPU index below: 183 MB against 502 MB for the default
# wheel, on a runner with no GPU. `torch==2.13.0` matches `2.13.0+cpu` — PEP 440 ignores
# the local version segment when matching.
#
# To re-resolve after changing a direct dependency:
#     pip install --dry-run --ignore-installed \
#       --extra-index-url https://download.pytorch.org/whl/cpu \
#       --report report.json -r <direct deps>
#
# Resolved 2026-08-30 against Python 3.14.6, which is what the repo's own
# interpreter runs and what the workflow now installs. Resolving pins on one minor
# version and installing them on another is a way to discover, unattended, that a
# pinned version has no wheel for the runner's Python.

--extra-index-url https://download.pytorch.org/whl/cpu
