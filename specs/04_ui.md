# Spec 04 — Demo UI (`ui/app.py`)

Read `SPEC.md` first. This is the demo face over data that already exists on disk. It reads
JSON written by the pipeline (notices.json, requirements.json, decision.json, profile.json) and
renders two views. NO business logic in the UI — it displays what the pipeline decided; it never
recomputes, re-judges, or re-classifies. If a tender lacks decision.json, show it as
"Not yet analyzed" — do not trigger analysis from the UI.

Run: `streamlit run ui/app.py`

## Layout

Sidebar:
- Product name from config.PRODUCT_NAME (never hardcode)
- Firm card from profile.json: firm name, certifications, bonding capacity, regions (compact)
- Sources line: "Sources: CanadaBuys open data + uploaded packages" (coverage honesty)
- Tender count by verdict

## View 1 — Triage feed (landing page)

Tenders grouped under three headers with counts: **Bid (N) / Review (N) / Don't bid (N)**
(then Not yet analyzed, collapsed). Within groups, sort by closing date ascending.

Each tender = one card:
- Title, tender_id, closing date (with "closes in N days" if < 14 — red if < 5)
- Verdict badge (color: green bid / amber review / red no_bid)
- The decisive line, verbatim pattern:
  - no_bid: "Blocked: {first blocker requirement_text} — p.{page}, {source_file}"
  - review: "{len(open_questions)} open questions — top: {first open_question text truncated}"
  - bid: "All {counts.mandatory} mandatory requirements pass"
- Counts strip: mandatory / passed / failed / uncertain
- Expander "Why?" → rationale paragraph + blockers/open_questions list, each item showing
  requirement_text, then the verbatim quote in st.caption style with "— p.{page}" suffix
- Button "Full compliance checklist" → switches to View 2 for that tender

## View 2 — Compliance checklist (per tender)

Header: tender title + verdict badge + closing date + back button.

Then requirements from requirements.json, bid-phase first:

**Section A — "Bid submission requirements ({n})"** (phase == bid_phase_mandatory), grouped by
category in this order: submission, bid_security, certification, insurance, eligibility,
evaluation, other_mandatory. Each requirement renders as:
- Status icon by qualification outcome: pass ✓ (green) / fail ✗ (red) / uncertain ? (amber) —
  from decision.json provenance (source: rule|explicit) if available
- requirement_text (normal weight)
- The proof line, visually distinct (st.caption or blockquote): "{verbatim_quote}" — p.{page},
  {source_file}
- If page_repaired: a small "page corrected" tag (this is a feature, show it)
- If machine_checkable: tiny caption "auto-checked: {check_field} {check_operator} {check_value}"

**Section B — "Contract conditions if awarded ({n})"** (phase == contract_condition),
collapsed expander, same rendering minus status icons.

Footer of the checklist: "Every requirement above carries a verbatim quote verified to exist at
the cited page. {dropped_count} unverifiable extraction(s) were dropped and are not shown."
(dropped_count from dropped.json — this sentence is the product thesis; render it.)

## Roadmap tab (locked-features conveyance, 15 minutes max)

Third nav item "Roadmap" — static markdown, no logic: weekly email digests, all-portal coverage
(MERX, bidsandtenders, provincial), one-click document capture extension, addenda conflict
detection, exportable checklist PDF. One line each. This is the platform-vision slide.

## Style rules

- st.set_page_config(page_title=PRODUCT_NAME, layout="wide")
- No custom CSS beyond minimal badge coloring (st.markdown with a few inline styles is fine);
  no external assets; must look clean on a 1440px laptop screen for video recording
- Every quote shown MUST come from verbatim_quote verbatim — never truncate a quote mid-way
  without ellipsis; page numbers always visible next to quotes
- Fast: load all JSON once per rerun with st.cache_data keyed on file mtimes

## Acceptance criteria

1. `streamlit run ui/app.py` renders the feed with all tenders under data/tenders/ that have
   decision.json; others under "Not yet analyzed".
2. Clicking through: feed → Why? expander → full checklist → back, with no state loss or crash.
3. A tender with a no_bid verdict shows its blocker with quote + page on the card without any
   clicks (the demo's money shot).
4. The checklist's Section A shows only bid-phase items with status icons; contract conditions
   are present but collapsed.
5. UI never calls OpenAI, never writes to data/ (read-only), never crashes on a tender with
   missing/empty files.

## Not in scope
Auth, editing profiles in UI (display only), triggering pipeline runs from UI, search, export.
