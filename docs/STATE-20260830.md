### Test suite — FAILING

Command: `.venv/bin/python -m unittest discover -s tests`

```
Ran 658 tests in 9.035s
FAILED (failures=2)
```

Wall time from `/usr/bin/time -p`: `real 11.59`, `user 8.53`, `sys 2.24`.

**Both failures are the same defect**, in `tests/test_notices_seao.py`:

- `test_an_active_works_notice_is_fully_normalized` — `tests/test_notices_seao.py:120`,
  asserts `record["status"] == "open"`, got `"closed"`.
- `test_active_tender_releases_stay_open` — `tests/test_notices_seao.py:139`, same
  assertion on `ocds-ec9k95-20004970`, got `"closed"`.

Mechanism, verified: the fixture release `ocds-ec9k95-20004970` in
`tests/fixtures/seao_releases.json` carries `tenderPeriod.endDate` of
`2026-08-27T11:00:00-04:00`. `normalize_status` in `notices/normalize.py:150` accepts an
injectable `now` parameter (`notices/normalize.py:153`) and falls back to
`datetime.now().astimezone()` at `notices/normalize.py:171`, marking a notice closed
once its closing date is past. `notices/seao.py:306` calls `normalize_status(...)`
without passing `now`, so the fixture's status flips with the wall clock. Today is
2026-08-30; the fixture deadline passed three days ago.

This is a time-dependent test, not an ingestion regression: the production behaviour
(closing a notice whose deadline has passed) is correct. The same defect class was
previously fixed elsewhere by injecting `now` — see `tests/test_notices_db.py`, which
does inject a clock.
